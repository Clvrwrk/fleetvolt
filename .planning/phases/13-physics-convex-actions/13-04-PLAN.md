# Plan 13-04: Retire Celery/Redis/sim-worker

<objective>
Remove the Celery worker, sim-worker, and Redis from the stack. The Convex simulate action (13-02) replaces the entire async job pipeline: no more POST /v1/simulations → Celery → poll GET /v1/simulations/:id. The web app calls the Convex action directly with inputsHash-based caching. The Python simulator service stays in docker-compose (for parity baselines until Phase 14), but the job queue infrastructure is gone.
</objective>

<execution_context>
Monorepo root: /Volumes/M4 Application SSD/Projects/FleetVolt. Docker stack: docker-compose.yml with 7 services (postgres, redis, simulator, sim-worker, api, web). This plan removes sim-worker + redis and deprecates the Fastify simulations routes. The Convex simulate action (13-02) is the replacement — it runs physics, persists results, and caches by inputsHash. The web app (apps/web) already has the Convex client configured (NEXT_PUBLIC_CONVEX_URL from Phase 7). The Fastify API (services/api) retains the PDF export route (moved to Convex in 13-05) and loses the simulations routes. The Python simulator (services/simulator) stays as the parity baseline source.
</execution_context>
