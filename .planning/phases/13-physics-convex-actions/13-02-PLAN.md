# Plan 13-02: Convex Action Wrapper + Charging/Feasibility/Orchestrator

<objective>
Wire the pure-physics functions from 13-01 into a Convex ACTION that runs the full simulation pipeline end-to-end. Port the remaining Python modules: charge curve, charging planner (using the Phase-12 Convex spatial layer for charger search), feasibility classifier, port drayage geo-fence, detour validator (Google Directions-based), and the orchestrator that chains them all. The `simulate` action reads truck configs + elevation profiles from Convex tables, runs physics, persists results to the simulations table, and returns a SimulateResponse. This is the vertical slice: a user can call `simulate` from the web app and get physics results — no Python, no Celery, no Redis.
</objective>

Phase 11 shipped: Google Maps + Google Directions/Routes API replaces Valhalla. The detour validator must use Google Directions (not PTV/Valhalla — Valhalla is retired). Convex constraints: action 10-min budget (sufficient for full pipeline), action arg 5MiB (route geometry payloads must be chunked if large), function return 16MiB. The Python orchestrator (orchestrator.py, 344 lines) is the source-of-truth pipeline: resolve endpoints → load truck → apply overrides → apply weather → get elevation → build segments → resolve speeds → port drayage → segment_forces → integrate_soc → KPIs → optional charging → feasibility → response. tsc clean except pre-existing scenario-form.tsx.

<name>Port charge curve + port drayage + detour validator</name>
<files>apps/web/convex/physics/chargeCurve.ts, apps/web/convex/physics/portDrayage.ts, apps/web/convex/physics/detourValidator.ts</files>
<action>
chargeCurve.ts: port integrate_charge_curve from charge_curve.py. Export integrateChargeCurve(curve: ChargeBreakpoint[], arrivalSoc, targetSoc, stationKw, usableKwh) returning {dwellS, energyKwh, departureSoc}. Step-wise: sort curve by soc_pct, iterate bands, seg_energy_kwh = (seg_end - seg_start)/100 * usable_kwh, effective_kw = min(band_max_kw, station_kw), dwell_s += seg_energy_kwh / effective_kw * 3600. Return 0,0,arrivalSoc if target <= arrival.

portDrayage.ts: port from port_drayage.py. Export PORT_SPEED_CAP_MPH=25, PORT_AUX_KW=18, segmentInPort(lon, lat) — point-in-polygon test against the POLB/LB harbor polygon. Load the polygon from data/geo/port_polb_lb.geojson at module init (embed the polygon coordinates as a TS constant since Convex actions run in Node and can't read files at runtime — bake the polygon into the module). applyPortDrayage(segments[], speedMph[], auxKw[], enabled) — copy arrays, if enabled iterate segments and cap speed + bump aux for in-port segment midpoints.

detourValidator.ts: port detour_seconds from detour_validator.py. Export detourSeconds(origin, charger, rejoin) — uses Google Directions API (fetch via Node fetch inside the Convex action context) to get direct (origin→rejoin) and via (origin→charger→rejoin) travel times. Return max(0, via - direct). The Google API key is available via process.env.GOOGLE_MAPS_API_KEY in the action context.
</action>

(4) apply weather via applyWeather. (5) get elevation profile from elevationProfiles table by corridorKey (or routeHash for custom routes). (6) build segments via buildSegments. (7) resolve speeds via resolveSpeeds (edge_speeds empty under Google Routes — falls back to DEFAULT_POSTED_MPH=55). (8) apply port drayage via applyPortDrayage. (9) segment_forces via segmentForces. (10) integrate_soc via integrateSoc. (11) aggregate KPIs. (12) if include_charging: run planGreedyStops + shadow pass + classifyFeasibility. (13) build SegmentResult[] + SimulateResponse. The ctx parameter provides ctx.db for Convex table reads.

simulate.ts: create the Convex ACTION. Export `export const simulate = action({ args: { request: v.any() }, handler: async (ctx, { request }) => { ... } })`. Steps: compute inputsHash, check simulations table for a cached completed run (by inputsHash), if found return cached results, else run orchestrator.runSimulation, persist to simulations table (status: "completed", results: response, durationMs), return response. Use a mutation to write the simulation record. The action runs within the 10-min Convex budget.
