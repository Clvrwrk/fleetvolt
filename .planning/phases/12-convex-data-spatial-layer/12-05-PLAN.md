<objective>
Execute P12-09: parse the POLB drayage carrier registry (3,151 rows), geocode every carrier address to lat/lon, tag each with a corridor-city, and ingest into the Convex `carriers` table so the flagship "which trucking companies to target" sub-answer (P12-10c) and the report query's carrier-density payload (P12-15a) are answerable. This registry is FleetVolt's unique, un-buyable asset — named carriers hauling out of POLB, with no API equivalent. The engineering focus is honest, cheap geocoding: it runs locally in Python with an on-disk cache (bill the ~3,151 geocodes once), conservative throttling + exponential backoff for the rate-limit open item flagged in RESEARCH §5, and a per-row geocodeStatus so failures are visible rather than silently dropped — carriers that fail to geocode are still ingested (location omitted) so counts stay honest. Located carriers are spatial-indexed via 12-02's insertPoint so carrier-density-within-radius works; all carriers are queryable by corridor city. The parity target is the flagship VERIFIED distribution (~1,824 active carriers, ~685 in-corridor, named clusters Long Beach/Wilmington/Carson/…) — the corridor-city aggregation must land near those clusters. Depends on 12-01 (carriers table) and 12-02 (spatial insert/nearest); Wave 2, parallel with 12-04/12-06. It does NOT compute hotspot scores (12-08 consumes carrier density as a proxy input).
</objective>
