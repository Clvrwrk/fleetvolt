# Phase 23 — UI Design Contract

> Visual and interaction contract for the desktop CaaS statewide route network, modeled prime charging candidates, and route-native executive brief. Generated by gsd-ui-researcher and awaiting gsd-ui-checker verification.

## Design System

| Property | Value |
|----------|-------|
| Tool | Existing FleetVolt Electric Command System + shadcn/ui |
| Preset | New York, neutral base, CSS variables, RSC |
| Component library | Existing shadcn/Radix primitives only; no third-party blocks |
| Icon library | Lucide; the prime-site marker uses the canonical FleetVolt SVG mark |
| Font | Arcline for interface and narrative; JetBrains Mono for telemetry/provenance; Brokline prohibited in application/report UI |
| Product surface | Command Dark for the CaaS map shell; Data Paper for evidence cards, live brief, tables, and PDF |

Reuse the current FleetVolt application shell, workbench rail, selection model, close-button behavior, loader, and shared data-paper card language. Do not introduce a second visual system, glassmorphism, generic SaaS cards, decorative imagery, or a new display font. This phase is desktop-only; tablet/mobile layout work is excluded.

## Spacing Scale

Declared values, inherited from the approved enterprise design system:

| Token | Value | Usage |
|-------|-------|-------|
| 3xs | 4px | Icon gaps, hairline offsets, compact status spacing |
| 2xs | 8px | Inline gaps, badge internals, table-cell subspacing |
| xs | 16px | Default control/card spacing and minimum text-to-edge clearance |
| sm | 24px | Panel padding, card groups, brief section internals |
| md | 32px | Major section padding and map/report split gap |
| lg | 48px | Desktop page gutters and briefing section breaks |
| xl | 64px | Cover/display breathing room only |

Exceptions: interactive targets are at least 44×44px; operating controls use 0–2px radius, evidence popovers use 8px radius, and circular geometry is reserved for map pins, status dots, and the FleetVolt mark. The CaaS rail may occupy up to 25% of the desktop viewport and an open drawer up to 80%, but neither may truncate decision-critical labels.

## Typography

Use exactly four shared typography roles and two weights in new Phase-23 UI. Each role defines its HTML and PDF equivalent; HTML and PDF must not introduce separate hierarchies. Existing hero/brand display outside this phase is unchanged.

| Shared role | HTML | PDF | Weight | Line Height (HTML / PDF) |
|-------------|------|-----|--------|--------------------------|
| Body / table / helper | 16px | 11pt | 400 | 1.6 / 1.35 |
| Label / control / strong body | 16px | 11pt | 700 | 1.4 / 1.25 |
| Card or subsection heading | 20px | 16pt | 700 | 1.2 / 1.2 |
| Page or major section heading | 32px | 22pt | 700 | 1.15 / 1.15 |

- No readable HTML text may be below 16px, including map legends, marker-card metadata, chart labels, captions, helper text, and download controls.
- PDF uses the same four named roles and their tabled point-size equivalents; no fifth display, caption, metadata, or print-only role is permitted.
- Arcline Regular (400) and Bold (700) are the only interface weights. JetBrains Mono inherits the same two weights for telemetry, units, provenance, timestamps, freshness, and status vocabulary.
- Brokline remains reserved for the public campaign signature `OWN THE TRANSITION` and must not appear in this phase.
- HTML must survive 200% browser zoom without clipped text, overlapping controls, hidden evidence, or horizontal document scrolling. Decision-critical names wrap; they never ellipsize.
- Use tabular numerals for route metrics, scores, units, dates, traffic, freight context, energy, emissions, distances, and carrier ranks.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Carbon `#07090C` | CaaS canvas, deepest chrome, map workbench shell |
| Secondary (30%) | Gunmetal `#121820`, Armor `#202A34`, Signal White `#F3F7FA` | Navigation/controls and task-assigned Data Paper evidence/report surfaces |
| Accent (10%) | Electric `#42A5D9`; Electric Deep `#20698E` on light surfaces | Primary action, focus ring, selected route edge, prime-site mark, active evidence link |
| Verified | Signal `#6FD49A` | Verified/ready evidence with text or icon |
| Attention / modeled | Safety Amber `#F0B84B` | Modeled candidate, caveat, incomplete validation with text or icon |
| Destructive / failure | Alert `#E4675B` | Failed load, invalid evidence, destructive action only |

Accent is reserved for the selected route, active control/focus, canonical FleetVolt prime-site mark, primary `Open route briefing` action, and active evidence/download link. Electric text below 24px on Signal White uses Electric Deep because plain Electric fails normal-text contrast.

Route data colors are a scoped analytic palette, not brand accent decoration:

- Measured truck AADT `<5,000`: Signal green; `5,000–<10,000`: Safety amber; `≥10,000`: Alert red. Equality enters the higher tier. Every color has the visible label `TRUCK AADT` and the numeric measured value/source.
- Port/FAF regional freight context uses route width and marching density only: low `3px`, medium `5px`, high `7px`. Motion cycles are respectively `2.4s`, `1.8s`, and `1.2s` and communicate direction. Thresholds come from the typed freight policy, not formatted strings.
- When defensible freight context is unavailable, render the measured-AADT color at a static `3px` baseline and label `Regional freight context unavailable`; do not invent a tier or display zero.
- Do not use color alone. The persistent legend names the channel, value, unit, provenance class (`MEASURED`, `REGIONAL CONTEXT`, `MODELED`), and unavailable state.

## Statewide Route Network

### Default map state

- The CaaS freight map represents the promoted 69-route catalog using only PTV road geometry with at least eight valid points. Never render endpoint chords or straight-line fallbacks.
- Route draw order is stable: geographic overlays, non-selected route network, point evidence, prime-site markers, selected route, selected marker/card.
- All route records use the same pure traffic/freight style policy in overview and focus. No separate blue focused-route truth may replace the measured AADT color; focus is shown with a neutral Signal White/Carbon casing and raised z-index while the data-colored core remains intact.
- At statewide scale, preserve map legibility by lowering non-selected network opacity, not by dropping verified routes. Prime markers may cluster visually, but each route keeps a distinct keyboard-accessible target and accessible name.

### Legend

The map legend is always reachable without opening a drawer and contains two separate rows:

1. `TRUCK AADT · MEASURED` — green/amber/red swatches, thresholds, daily-truck unit, Caltrans source and as-of date.
2. `REGIONAL FREIGHT CONTEXT` — low/medium/high stroke samples, source/scope, animated-direction note, and explicit unavailable sample.

Legend copy must state: `Color shows measured truck AADT. Width and pulse show port/FAF regional context; they do not measure traffic-generator throughput.`

### Route selection and persistent focus

- Pointer or keyboard activation selects a route, fits the actual PTV path, raises it above the network, and filters unrelated evidence.
- Focus is a persistent route state. Activating or closing a prime-site card, selecting another route-related marker, panning, or zooming must not clear it.
- Only the explicit `Show all map layers` control clears focus. The control remains in a stable location while focused, has a 44px minimum target, and returns the map to the statewide network without destroying the selected catalog record.
- The selected-route summary exposes origin → generator name, road distance, geometry freshness, AADT value/tier/source, freight-context tier/source or unavailable reason, and `Open route briefing`.

### Network states

| State | Contract |
|-------|----------|
| Loading | Keep the map/shell stable; show the FleetVolt loader with `Loading verified route network…`; do not flash synthetic arcs. |
| Partial | Show verified promoted routes only and state `X of 69 verified routes available`; missing pairs are not drawn. |
| Empty | Heading `Route network unavailable`; body `No verified road routes are available. FleetVolt will not draw straight-line substitutes.`; action `Retry route evidence`. |
| Error | `Route evidence could not be loaded. The last verified map remains visible when available. Retry.` |
| Freight unavailable | Route remains visible from measured AADT; baseline width is used and the legend/card explains the unavailable regional context. |

## Prime Charging-Site Marker

### Marker anatomy

- Use the exact FleetVolt 96×96 mark geometry: orbit, clockwise Electric trace, Electric bolt. The interactive target is 48×48px; the visible mark is 40px and keeps identical visual mass across all candidates.
- The marker label is `Modeled prime charging candidate for {port} to {generator}`. Use a semantic button inside the Advanced Marker; Enter and Space activate it.
- The bolt never rotates at rest. A fixed-size outer energy halo pulses from 100% to 108% scale and 35% to 10% opacity over 2.4s. The marker box does not move or resize. `prefers-reduced-motion` removes the pulse and presents a static Electric outline plus visible `PRIME` status.
- Selected state adds a Signal White casing and Electric focus ring; it does not recolor the route or imply verification.

### Interaction

- Marker activation opens the explanation card and retains route focus, active layer profile, route geometry, and selected route. It may pan only enough to keep the marker and card visible; it must not reset map bounds to statewide view.
- The card includes a visible Close button and supports the existing double-click close behavior. Closing the card clears only the selected marker/card, never route focus.
- If markers overlap, a cluster is keyboard reachable and expands without choosing a candidate implicitly.

### Explanation card

Use a Data Paper surface anchored at the right/bottom of the map, maximum width 36rem, maximum height `calc(100dvh - 5rem)`, 8px radius, 24px padding, and internal scrolling only when necessary. The card order is fixed:

1. Eyebrow `MODELED CHARGING PRIME CANDIDATE` plus `MODELED` status.
2. Candidate/site name and route name.
3. One-sentence decision summary: why this is the highest-ranked candidate for the standard 438-kWh Class 8 planning profile.
4. Metric band: modeled arrival SoC, detour miles, site type, overall score/confidence.
5. `Why this location` score components: energy-window fit, HGV dwell suitability, charger-gap evidence, freight demand context, detour, evidence completeness. Show numeric component and plain-language interpretation; do not expose raw IDs or raw OSM objects.
6. Evidence table: source, method, scope, freshness/as-of, and status for each material input.
7. Amber caveat: `Modeled siting hypothesis — parcel access, trailer circulation, utility capacity, permitting, and live charger status require field validation.`
8. Primary action `Open route briefing`; secondary action `Close`.

If no mapped freight-compatible site qualifies, the same card renders the on-route fallback with heading `MODELED ON-ROUTE CANDIDATE`, status `HUMAN REVIEW`, and the field-validation caveat above. It must not use `VERIFIED` language.

## Route-Native Executive Brief

### Information architecture

The live brief is a semantic Data Paper document inside the Command Dark application shell. It is keyed by the selected catalog route and contains no synthetic carrier, route, energy, emissions, or economic values. Use this deterministic order:

1. Cover: port → generator, report status, catalog route, geometry/enrichment freshness, generated date.
2. Executive decision summary with four headline values: road distance, measured truck AADT, regional freight context or unavailable, modeled prime-site confidence.
3. Route method: PTV road geometry, cache receipt/freshness, standard 438-kWh profile, limitations.
4. Road-level route map with visible AADT/freight legend, prime-site mark, caption, and tabular route-node alternative.
5. Truck traffic and regional freight demand, kept in separate evidence panels.
6. Charger coverage, Class 8 gaps, parking/dwell evidence, and prime-site rationale.
7. Route-proximate amenities, fleet yards, and traffic generators within the inclusive 10-mile detour policy.
8. Air district, county, and ZIP context.
9. Verified/geocoded carrier targets: zero to ten; never padded. A zero-result state is valid.
10. Modeled energy and emissions for the standard profile with named planning factors and no claim of measured operations.
11. Risks, assumptions, unavailable evidence, data quality, and required field validation.
12. Recommended next actions, sources, evidence appendix, and download controls.

### HTML contract

- Use semantic `main`, `article`, numbered `section`, headings in order, `figure`/`figcaption`, `table`/`caption`, `dl`, and real links/buttons.
- Content maximum is 1128px. Default document uses a 61.8% evidence/narrative column and 38.2% decision rail where two columns improve comprehension; at 200% zoom it becomes one column without data loss.
- A persistent document header contains Back, route name/status, `Download PDF`, `Export CSV`, and `Export JSON`. Downloads are secondary to the primary map action `Open route briefing`.
- Every material value includes unit, provenance class, source/method, scope, and as-of/freshness. Unknown is `Unavailable — {reason}`, never zero or an empty cell.
- Route maps/charts have concise alt text and an adjacent table with the equivalent values. Charts do not use color as the only series distinction.
- Carrier empty copy: `No verified carrier targets qualify within the route proximity policy. FleetVolt has not padded this list.`
- Energy/emissions label: `MODELED PLANNING ESTIMATE · STANDARD 438-kWh CLASS 8 PROFILE`; list the named fuel/grid factors and generated timestamp.

### PDF contract

- US Letter portrait, 0.5in margins, Signal White/white Data Paper, Carbon body text, and Electric Deep for normal-size link/accent text. Body/table copy uses the shared `Body / table / helper` role: 16px in HTML and its 11pt PDF equivalent.
- Repeat document title, route, evidence status, generated date, and page number in page furniture. Repeat table headers across page breaks and never split a carrier/evidence row.
- The PDF contains selectable embedded text, embedded/fallback-safe fonts, tagged heading/table structure where the renderer permits, descriptive captions, and a source appendix.
- HTML and PDF headline values, units, statuses, dates, and unavailable reasons must match exactly. PDF generation may paginate or simplify interactive controls but may not change evidence.
- Map and chart rasterization must be high-resolution and accompanied by the same tabular alternative as HTML.

### CSV and JSON controls

- Controls are labeled `Export CSV evidence` and `Export JSON evidence` and include the route name in the accessible description.
- Both appendices follow the deterministic evidence schema/order used by HTML/PDF and include source, method, scope, status, as-of/freshness, units, raw numeric value when available, and unavailable reason.
- Successful download announces the filename with `aria-live="polite"`; failure states say what failed and provide `Retry export`.

## Motion and Loading

- Micro response: 120–180ms. Drawer/card transition: 220–300ms. Route/data reveal: 350–700ms.
- Route pulse is evidence encoding, not decoration, and stops under `prefers-reduced-motion` while route width and legend preserve the freight tier.
- Prime-site halo stops under reduced motion. The FleetVolt loading trace may rotate at 1.2s; the loading bolt rotates once at the start and no more than once per 60s.
- A blocking route/brief operation uses a 50%-transparent gray overlay, centered FleetVolt loader, and explicit current task. Do not use an inert gray button as the sole progress signal.
- Motion never changes layout, steals focus, or prevents activation.

## Accessibility and Verification

- WCAG 2.2 AA minimum; 44×44px target preference; visible 2px focus ring with 2px offset; logical keyboard order; no hover-only evidence.
- The map provides a keyboard-accessible route list/table alternative containing every promoted route and prime candidate. Map-only interaction cannot be the sole path to the brief.
- Marker, route, legend, card, table, and download controls have unique accessible names. Status changes use `aria-live="polite"`; errors use an alert only when immediate action is required.
- Verify desktop at 1440×900 and the approved minimum desktop width. Tablet/mobile behavior is explicitly not an acceptance gate.
- Required visual states: statewide network + two-channel legend; selected/focused route; selected prime marker + full explanation card; reduced-motion marker; HTML cover/summary; route map/evidence page; zero-carrier state; unavailable-freight state; print/PDF sample.
- Visual acceptance must prove text is ≥16px in HTML, data does not truncate, route focus survives prime-marker activation and card close, colors/widths reconcile to typed evidence, and no mock data or raw internal identifiers appear.
