<threat_model>
**Trust Boundaries**
- TB1: Browser client ↔ Convex deployment (unauthenticated in P7 — anyone with the public URL can read/write). Acceptable for a single-viewer demo; hardened by WorkOS in P10 (D-06).
- TB2: Build/dev machine ↔ npm registry (new dependency installs).
- TB3: Client env (NEXT_PUBLIC_* keys) — Google Maps key and Convex URL are shipped to the browser by design.

**STRIDE register**
| ID | Threat | Category | Mitigation |
|----|--------|----------|------------|
| T-07-SC | Malicious/typosquatted or compromised npm package pulled during the phase's dependency install | Tampering/Elevation | All installs isolated to THIS plan; pinned exact versions verified in 07-RESEARCH.md § Package Legitimacy Audit (all first-party, 0.6M–15M downloads/mo, no typosquats); resolved versions recorded in convex/README.md; pnpm lockfile committed. |
| T-07-01a | Unauthenticated Convex writes let a demo viewer mutate userFilters/data | Tampering | Accepted risk for P7 demo scope (D-06); data is illustrative; write surface limited to userFilters.upsert; auth boundary lands P10. |
| T-07-01b | NEXT_PUBLIC_GOOGLE_MAPS_API_KEY leaked/abused (it is public by necessity) | Info Disclosure/DoS | user_setup mandates HTTP-referrer + API restriction on the key to the demo domain + localhost. |
| T-07-01c | A record inserted without provenance silently erodes data credibility | Repudiation | Shared provenance validator + assertProvenance + provenance-contract.test.ts make missing provenance a compile/test failure (DINT-01/SRC-01). |
| T-07-01d | Convex client re-instantiated per render → reconnect storms | DoS | Client instantiated at module scope once (Pitfall #5). |
</threat_model>
