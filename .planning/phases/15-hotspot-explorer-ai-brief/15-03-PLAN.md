<objective>
Deliver the third vertical slice: clicking a hotspot now generates an LLM-powered executive sales brief grounded in the real report data. The Convex action `generateSalesBrief` fetches the `hotspotReport` payload, constructs a prompt per the 15-AI-SPEC grounding contract (system prompt with honesty rules + the full report JSON as grounding context), calls the OpenAI Chat Completions API, and returns the brief. If no LLM key is provisioned, a structured fallback brief is assembled from the report fields (still grounded, just template quality). The BriefPanel renders the brief as markdown with a model/grounded/fallback header and a regenerate button. Honesty guardrails are enforced both in the prompt and in brief.test.ts: the brief must say "modeled" (never "observed dwell"), must include a Data Disclosure section, and every number must trace to the report payload.
</objective>

<threat_model>
**Trust Boundaries**
- TB1: LLM output ↔ grounding data (the LLM may hallucinate numbers not in the report payload).
- TB2: LLM API key ↔ Convex action sandbox (key must be in Convex env, not client-visible).
- TB3: Modeled-score honesty label ↔ LLM output (the LLM must say "modeled", never "observed").

**STRIDE register**
| ID | Threat | Category | Mitigation |
|----|--------|----------|------------|
| T-15-03a | LLM fabricates numbers not in the report payload | Tampering | System prompt: "every number MUST come from the provided report data"; brief.test.ts extracts all numbers and asserts they appear in the payload; temperature 0.3 reduces creativity. |
| T-15-03b | LLM says "observed" instead of "modeled" | Repudiation | System prompt rule #1: "Never say observed/measured/actual dwell data"; brief.test.ts asserts "modeled" present and "observed dwell" absent. |
| T-15-03c | OPENAI_API_KEY leaked to client | Information disclosure | Key is in Convex env (process.env inside action), never sent to client; the action is called via useAction which runs server-side in Convex. |
| T-15-03d | LLM API call fails/hangs | Denial of service | Action has graceful error handling: non-200 → fallback brief; fetch timeout → fallback brief; client shows fallback banner. |
| T-15-03e | LLM omits the Data Disclosure section | Repudiation | System prompt mandates the section; brief.test.ts asserts its presence. |
| T-15-03f | Fallback brief fabricates data | Tampering | buildFallbackBrief only uses fields from the report payload (carriers.length, totalSpots, class8WithinRadius, etc.); no hardcoded numbers. |
</threat_model>
